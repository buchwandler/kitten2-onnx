# Upstream emb4 source reader

`kitten2_onnx/tl2_emb4.py` ports the tensor layouts and reconstruction equations from the upstream [`kittenml/kittentts2/tl2_emb4.py`](https://github.com/KittenML/KittenTTS/blob/main/kittenml/kittentts2/tl2_emb4.py) reader.

The reader accepts the released schema name `kitten_ternary_tl2_rl_v1` and the compatible older alias `kitten_ternary_tl2_emb4_v1`. It validates the TL2 byte geometry, vocabulary dimensions, tier map, codebook sizes, code lengths, codebook tensors, and scales before reconstruction. `read_emb4_embedding_payload` reconstructs only the vocabulary. `iter_emb4_tensors` yields reconstructed tensors one at a time, decoding embedding rows in configurable chunks. `load_emb4_state_dict` is the explicit full-state convenience API.

`tests/test_emb4.py` uses small generated TL2 and tiered-codebook fixtures to compare decoded values with the upstream equations, including Hadamard rotation and scale restoration. At pinned upstream model revision `fa8ce5c7547e322a065cad9b813d27a78fad9640`, the full 492 MB emb4 checkpoint was compared with the installed upstream `kittenml.kittentts2.tl2_emb4.dequant_embedding` implementation. The reconstructed BF16 table matched the upstream loader exactly, element for element. Against the full BF16 checkpoint embedding, relative L2 error was 0.11391475 and maximum absolute error was 0.06787109. Relative L2 by tier was 0.01945937, 0.11808104, and 0.11583712. The resource-guarded comparison peaked at 5.33 GiB RSS and took 27.56 seconds on this host. The machine-readable report is `build/reports/emb4-upstream-reference.json`; this validates embedding reconstruction only, not LM logits, generation, or audio parity.
